# Windows 存储扫描与空间核算

用于 Windows 存储盘点、大目录下钻和清理前后比较。它是扫描结果的解释契约，不是清理规则；执行边界仍见 [cleanup-protocol.md](cleanup-protocol.md)。

## 选择扫描方式

先用 `Win32_LogicalDisk` 核实目标卷、文件系统和空闲字节，用 `Get-Item -LiteralPath` 检查具体目录及其祖先的 reparse point。不要按卷名、扩展名或 VHDX 文件名猜测文件系统。网盘虚拟卷按 [windows-storage-inventory](playbook-windows-storage-inventory.md) 排除。

| 场景 | 选择 | 结果边界 |
|---|---|---|
| 已知应用目录、小范围盘点、普通权限 | 有时间/条目数预算的文件系统枚举 | 记录拒绝访问、链接跳过和预算耗尽；不能称为 MFT 快速扫描 |
| 已安装并审查过的工具支持目标文件系统，且确实需要大范围索引 | 可选 NTFS MFT / ReFS 元数据扫描 | 先核验版本、来源、权限和实际支持的文件系统版本；原始索引可能读取整卷元数据，须确认这一范围 |
| 快速后端不可用或用户不批准提权 | 缩小范围继续普通权限枚举，或交付部分报告 | 明示实际后端、失败原因和缺失范围；不自动安装二进制、修改权限或无限重试 |

本项目不捆绑原始磁盘扫描器，也不保证扫描速度或 ReFS 全版本兼容。参考仓库在复核版本中只声明支持 ReFS 3.14 原始扫描；不能把该限制推断为所有扫描器的能力。调用外部工具前读取 [rule-source-contract.md](rule-source-contract.md)，不要把它的默认提权或删除入口继承为本 Skill 的默认行为。

## 扫描与展示分开

1. 先返回目标卷基线和一层目录概览，再对占用较大的具体子目录下钻。目录本身的元数据不能提供后代文件总大小；未测量的项标记 `pending`，不填 0。
2. 扫描范围与展示范围分开记录：`scan_depth`、时间/条目预算决定覆盖范围；`display_depth`、`top`、`min_size` 仅裁剪展示。只有索引确实完整时，才可在不复扫的情况下从缓存展开任意子树。
3. 默认展示 Top 20 或更少的条目及其余已扫描项的汇总，避免把全盘文件名带入上下文。“其他已扫描项”与“未扫描/无法访问”必须分开，后者的大小是未知。
4. 拒绝访问、预算耗尽、消失条目和链接不阻塞其他独立目录；记录受影响的子树。若深度上限让后代尚未枚举，父目录总量也是部分值。对较大 HDD 或网络路径减少并发，不为更快输出重复全盘递归。

报告或快照至少保留这些字段；宿主字段名不同可映射，但不能丢失含义：

| 字段 | 含义 |
|---|---|
| `scan_id`, `started_at`, `finished_at` | 本次扫描身份和 UTC 时间窗口 |
| `scope`, `volume_id`, `filesystem` | 字面根路径、卷身份和文件系统；本地报告保留，外发时脱敏 |
| `backend`, `tool_version`, `metric` | 实际扫描方式、工具版本、排序采用 logical 还是 allocated |
| `scan_limits`, `exclusions`, `complete` | 实际预算、主动排除项与覆盖是否完整；`complete` 仅对声明的范围成立 |
| `errors`, `skipped`, `unknown_scopes` | 错误、跳过理由和缺失范围；不能将失败清零后宣布全盘完整 |
| `logical_bytes`, `allocated_bytes` | 逻辑长度与实际分配量；测不到的值为 `null/unknown` |
| `file_count`, `latest_file_write_utc`, `oldest_file_write_utc` | 已扫描后代文件数、最新和最早的文件写入时间 |

目录的最新/最早时间取后代**文件**写入时间的 max/min，不混入目录本身时间；空目录没有文件时间。最早时间只能说明含有旧文件，最新时间也不能证明最近使用或可以删除。部分扫描的时间范围同样标为不完整。

## 快照复用与比较

- 只在本机保存用户需要的报告或索引；先核对目标空间，避免把大索引写进快满的卷。报告放在被比较子树之外，保留快照版本、范围、排除项和时间。索引包含敏感路径，不上传。
- 复用前核对卷身份、范围与兼容版本；旧快照只用于解释和候选计划，不能替代执行前的现场检查。没有完整索引时，只重扫用户展开的具体子树。
- 比较相同范围、指标、排除项和文件身份口径下的完整记录，统计新增、消失、大小/时间变化。差异样例可限量，不能只比较 Top N 行或终端截断文本。
- 任一快照不完整时，只能报告已观察到的差异，不能声称范围完全相同、全部清理或某个未出现的文件已经删除。目录持续写入时，说明扫描并非同一时刻的原子快照。
- 执行前重核字面路径、祖先链接状态、类型、文件身份（可用时）、大小、时间和清单要求的哈希。发现替换或变化就跳过并刷新；普通路径检查不等同于工具提供的防替换句柄保障。

## 空间账本

PowerShell 卷基线必须保留字节，不只保留四舍五入后的 GB：

```powershell
Get-CimInstance Win32_LogicalDisk -Filter 'DriveType=3' |
  Select-Object DeviceID, VolumeName, FileSystem, Size, FreeSpace
```

分别报告：

- `processed_logical_bytes`：成功处理的文件逻辑大小，代表处理量。
- `estimated_reclaimable_bytes`：排除重复计数和共享块后仍有不确定性的预计释放量；无法核实就标未知，不把逻辑大小直接复制到此字段。
- `free_before_bytes` / `free_after_bytes` / `observed_free_delta_bytes`：同一卷和同一查询口径下的实测差值，允许为负；注明采样时间和同时发生的下载、日志、同步等写入。

硬链接按卷身份和 File ID 去重；不能取得身份时说明可能重复统计。稀疏/压缩文件、ReFS 克隆和去重共享块，即使拿到 allocated 大小也不保证删掉一条路径后释放等量空间。`WinSxS` 以 DISM 分析为准。

**同盘回收站或隔离目录仍占用原卷空间。** 把 10 GiB 文件移入同盘隔离区，只能报告“已隔离 10 GiB”，不能报告“释放 10 GiB”。需要真正腾空间时，优先规划跨卷复制并验证；清空回收站是单独的不可逆动作，仍受批次回滚约束，不能顺手执行。WSL/VM 内删除与宿主虚拟磁盘压缩也分开核算。
