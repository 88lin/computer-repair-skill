# 清理协议

本协议把桌面清理器常见的“规则、扫描、执行、恢复”模型转换为宿主 Agent 可审计的流程。适用于缓存、应用残留、启动项、服务、计划任务、浏览器外部宿主、右键菜单、文件关联和 Appx 等清理请求。

## 模式与边界

按以下顺序推进，不跳过中间阶段：

1. `inventory`：只读枚举和分类，确认机器、用户、权限、路径与管理策略。
2. `analyze/preview`：解析已审查的规则，生成具体文件、注册表项、服务或任务的命中清单，不改变状态。
3. `apply`：用户确认清单后逐项执行，范围扩大或证据变化就暂停并重新计划。
4. `verify`：用相同范围复扫，核对目标消失/状态变化、空间差异和相邻功能。
5. `restore`：按备份批次恢复，恢复后再次复扫并报告无法恢复的项。

“清理”“优化”“一键处理”都不等于授权。定时任务或无人值守调用默认只允许 `inventory` 和 `analyze/preview`；不要从其他清理器继承静默删除、自动关机或“保存上次选择即执行”的行为。

## Finding 与规则模型

每个命中项都应至少保留：

- `id`、类别、用户可读名称、实际影响和技术位置；
- 证据来源（显示名、Publisher、产品/版本、签名、安装目录、命令、注册表/任务 XML、哈希）及采样时间；
- 动作类型：`report-only`、删除值、删除键、移动到隔离、禁用服务/任务、启动官方卸载器；
- 风险、是否需要管理员权限、是否可批量选择、警告与明确排除理由；
- 预览时的路径/大小/哈希或原状态，以及备份路径、执行结果、退出码和复核结果。

规则应分开描述：检测条件（OR 命中即可）、正向目标、排除项、默认是否选中、警告、动作、回滚和验证。没有正向目标或只有宽泛通配符的规则不进入执行阶段。

## 分析阶段

- 只解析具体且可追溯的规则；对每个目标展开环境变量和通配符，列出字面绝对路径、类型、大小、时间、所有者和来源规则。
- 不跟随 junction、symlink 或其他 reparse point；锁定、拒绝访问、已消失或哈希变化的项目标记为 `skipped`，不要用强制句柄或重试掩盖问题。
- 区分注册表“值”和“键树”，区分“文件移动到隔离”与“永久删除”，区分“禁用”与“删除”。浏览器 profile、凭据、邮件/聊天数据库、同步根目录和主程序默认仅报告。
- 显示命中数量、总字节、预计权限、警告、排除数量和无法确认的项目。证据不足或多个厂商强证据冲突时只能 `report-only`，不能靠 GUID、哈希、PID、系统宿主名或路径子串单独认定归属。

## 执行与批次

用户确认时引用固定的 finding ID 和目标列表。对每一项：

1. 重新检查目标存在、路径未越界、大小/哈希或原状态未改变。
2. 先备份：注册表导出，文件移动到回收站/隔离目录，服务保存启动类型与状态，计划任务保存 XML 与启用状态。
3. 备份文件可读取后才执行单项动作；失败时保留原状并记录原因。
4. 执行后立即复核该项，记录退出码、动作时间、恢复位置和新状态。

每批次写入独立清单，至少包含 `created_at`、主机/用户标识的最小必要部分、规则来源、批准范围、逐项 before/after、backup、status、verification 和 rollback。清单不得包含密码、Cookie、令牌、私钥或完整用户目录。

## 验证与恢复

清理完成后重跑原始规则和相邻功能检查。仍命中的项、动作返回成功但状态未变的项、锁定项和被策略重新创建的项必须保留在结果中。恢复时拒绝越出本批次备份根目录的路径；目标已有同名文件时不覆盖，报告人工合并。
