它不是什么

它不是装机软件，而是一套让 Agent 按步骤诊断、解释风险，并在你确认后修复问题的电脑维修流程。

一次对话怎么走

从描述问题到验证结果，Agent 始终按七个步骤推进。任何修改都要先说明原因、影响和回滚方式，再等待你确认。

  1. 01明确目标
  2. 02路由 Playbook
  3. 03只读诊断
  4. 04提出修复计划
  5. 05执行最小变更
  6. 06验证结果
  7. 07收尾
  1. 1

    明确目标

    把请求拆成症状、目标状态和不可改变的约束。多个目标逐项保留——不用删除替代迁移，不用重装替代修复，不跳过明确要求。

    动作分级：只读审计 · 可逆变更 · 高影响变更 · 系统级红线

  2. 2

    路由 Playbook

    读取路由索引，按症状、平台和触发词选最具体的一个 Playbook。只加载当前任务需要的那一份，不一次读全部。

    Playbook 是诊断协议，不是执行授权

  3. 3

    只读诊断

    先跑范围窄、不改状态的检查，记录命令、退出码、测量值、路径、服务状态和时间点。命令输出是证据，单一异常不等于根因。

    默认只传元数据：不读文件正文、密码库、Cookie 或私钥

  4. 4

    提出修复计划必须停下

    在安装、升级、长时间任务、管理员操作或任何状态变更之前，先展示：已确认的现象与最可能原因、具体动作和影响范围、是否需要提权／联网／重启、回滚点、修复后的验证命令和成功标准。

    等待用户明确确认。之前对另一组动作的确认，不覆盖新出现的高影响动作。

    整个 Skill 的支点在这里

  5. 5

    执行最小变更

    只执行已经展示过的动作；范围一扩大就重新展示计划。用字面路径和结构化参数，不依赖当前目录或宽泛通配符。清理逐项留下目标路径、大小／哈希、原位置、时间和恢复位置。

    优先回收站或隔离目录，不用永久删除代替「清理」

  6. 6

    验证结果

    重跑与故障直接相关的诊断，不以命令退出成功代替问题解决。对比变更前后数据，并检查相邻功能是否回归。

    Playbook 定义了成功标准时逐项满足

  7. 7

    收尾

    用你当前的语言简洁报告：根因或当前最可信结论、实际执行的命令与改动、验证证据和最终状态、尚未处理的风险与回滚命令。

    不声称已修复未经验证的问题

安全红线

删除文件、使用管理员权限、修改磁盘或启动配置都可能带来高风险。Computer Repair Skill 会按影响分级，越危险的动作，需要越明确的范围、回滚方案和单独确认。

用户对普通修复的确认，不覆盖这些对象。

Computer Repair Skill·系统级红线

四级风险分层

  1. L1

    只读

    观察系统但不改变状态，例如查询网络、磁盘、进程、服务、日志和文件元数据。

    限定范围后可直接执行
  2. L2

    可逆变更

    低影响且有明确回滚，例如刷新 DNS、重启普通服务、移动单个文件。

    先展示计划、影响和回滚，取得确认
  3. L3

    高影响变更

    删除、终止进程、清缓存、改权限、安装、升级、卸载、管理员命令、批量移动、修改启动项或安全设置。

    展示精确命令、目标范围、恢复方案和验证，单独确认
  4. L4

    系统级红线

    启动卷、系统根目录、分区表、固件、BIOS/UEFI、系统密钥链、凭据数据库、整棵用户目录，或关闭核心安全机制。

    停止执行，转向厂商或企业恢复路径

删除前必须走完的六步

Inspect Before Delete · 对任何删除都适用

  1. 用字面绝对路径确定目标，不依赖当前目录。
  2. 用只读命令列出目标、大小、修改时间、类型和关键内容。
  3. 确认检查结果确实对应将删除的具体对象。
  4. 展示目标列表、理由、预计影响和恢复方式。
  5. 取得用户对本次具体目标的确认。
  6. 删除明确子项，随后验证目标与相邻目录状态。

绝不执行

这些写法根本不进入执行阶段

  • 把远程响应直接交给 Shell 的管道：irm | iex、iwr | iex、curl | powershell、curl | bash、wget | sh、bash -c "$(curl …)"。
  • 对用户数据、应用数据或凭据目录使用 *、递归根目录或祖先目录清扫。
  • 通过管道、xargs、eval、命令替换、编码载荷或动态变量隐藏删除目标。
  • 在聊天中输出密码、恢复密钥、私钥、token 或完整敏感路径。
  • 主动关闭 Defender、SmartScreen、UAC、防火墙、Windows Update 或核心隔离——这些只做状态审计。
  • 盗版激活、未知下载器、强制卸载 Edge、未审计的一键优化包。

每个高影响动作都留一条记录

时间 | 目标 | 动作 | 风险级别 | 用户确认 | 退出状态 | 验证 | 回滚

记录命令模板时移除秘密；路径涉及用户名或公司信息时只保留诊断所需部分。

装进你的 Agent

四种方式，从「一句话交给 Agent」到「手动复制目录」。只支持聊天、不具备本机文件或终端能力的客户端，无法替你真正安装。

把一句话交给 Agent

最适合新手。打开 Codex、Claude Code、Hermes、OpenClaw、Cursor 或其他支持 Agent Skills 的工具，把右边这段话直接发给它。

Agent 需要能访问 GitHub、读取本机文件并执行必要的安装命令。

Skills CLI

已装 Node.js 和 npm 时最快。第一次运行会让你选择安装范围和目标 Agent；装完重启或刷新 Agent 的 Skills 列表。

安装范围、目标 Agent 和链接来源以 Skills CLI 当前文档为准：skills.sh/docs。

仓库安装器

适合希望明确控制路径的用户。codex、claude、agents 会使用对应的默认 Skills 根目录；custom 配合 -Destination / --destination 自定义位置。

目标目录已存在时安装器默认拒绝覆盖。确认升级时显式加 -Force 或 --force，旧版本会先备份到相邻的 external/computer-repair-skill/backups。

手动复制

适合无法使用命令行的用户。把仓库里的 skills/computer-repair-skill 整个目录复制到目标 Agent 的 Skills 根目录。

目录中必须保留 SKILL.md、agents/ 和 references/，不要只复制某一个 Playbook。
